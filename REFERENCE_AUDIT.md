### Key Findings

1. **The `data/anomalies/packages/` directory** contains thousands of auto-generated package directories (each with `sources.yaml`, `lead_record.json`, `README.md`). These are **NOT referenced from any source code** — they appear to be internal analysis package containers, not consumed by any script or app.

2. **`site/results/`** is a public mirror of `data/anomalies/conclusions/`. The application code (`app/server.py`) reads from `data/anomalies/conclusions/` directly at runtime; `site/results/` is built by `build_site.py` for GitHub Pages deployment.

3. **`site/report/`** is an orphan — exists on disk but not referenced by any code, server route, or documentation beyond the README line.

4. **All `.log` and `.err` files** in `data/` root are generated artifacts with no source code references, except `data/raw/downloads.log` (actively written by download scripts).

5. **`data/logs/launcher.log`** is only mentioned in a developer comment in `app/launcher.py` — the code doesn't actually create this file.

6. **`build/` and `dist/`** are purely PyInstaller build outputs. No source code reads from them at runtime.
